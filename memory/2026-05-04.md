## hCaptcha 调试记录 (续 - 晚8点)

### Lever hCaptcha 架构分析
Lever 使用 hCaptcha **enclave 模式**（embedded），application.js 中：
1. `onLoad` 调用 `hcaptcha.render('h-captcha', {sitekey, callback: onSuccess, expired-callback: onExpired})`
2. `captchaId = hcaptcha.render()` 返回 widget ID（enclave 模式下 `data-hcaptcha-widget-id` 为空）
3. `locationInput.focus` → `hcaptcha.execute(captchaId)`（聚焦时自动触发）
4. `submitBtn.click` → 
   - 有 token → 直接 `clickSubmitButton()`
   - 无 token → `executedFromSubmitButton=true; hcaptcha.execute(captchaId)`
5. `onSuccess(token)` → `hcaptchaResponseInput.value = token` → 如 `executedFromSubmitButton` 则 `clickSubmitButton()`

### 关键发现
- `captchaId` = `hcaptcha.render()` (enclave 模式 ID)
- `hcaptchaResponseInput` (id) = 存储 token 的隐藏输入
- `hcaptchaTokenExpired` (bool) = 过期标志
- `executedFromSubmitButton` (bool) = 是否从提交按钮触发
- `clickSubmitButton()` = 在 IIFE 闭包中的提交函数，window 上不可直接访问
- `onSuccess(token)` = 全局可访问的回调

### Token 注入方案（当前实现）
```javascript
// 设置变量
inp.value = token
window.hcaptchaTokenExpired = false
window.executedFromSubmitButton = true

// 调用回调
window.onSuccess(token)

// 触发提交按钮（Lever 的 addEventListener handler 检查 token 后提交）
btn.dispatchEvent(new MouseEvent('click'))
```

### 2Captcha 表现
- ✅ 成功时：~20 秒拿到 token，余额 $2.99
- ❌ 不稳定：有时 40+ 秒超时，偶尔完全不返回
- 可能原因：hCaptcha 排队时间长，或免费/低价账户优先级低

### 最终发现（晚8点）：2Captcha token 被 Lever 服务端拒绝

#### 提交方式对比
| 方式 | 结果 |
|------|------|
| 点击提交按钮 + token + onSuccess + executedFromSubmitButton | 无任何网络请求 (clickSubmitButton 闭包中阻止了) |
| `form.submit()` (native) | ✅ 发出 POST 请求到 /apply 端点 |
| valid PDF 简历替换 | ✅ 不影响（316 字节有效 PDF ok） |

#### 决定性测试
- `form.submit()` 触发了 POST 请求 → HTTP **400** Bad Request
- 页面显示："There was an error verifying your application. Please try again."
- 用 `invisible=1` 参数也不行
- 用 2Captcha API v2 (HCaptchaTaskProxyless) 也不行
- 新鲜 token（获取后 <5 秒内提交）也不行
- 2124 和 2026 字符两种不同格式 token 都被拒绝

**结论：2Captcha 返回的 hCaptcha token 虽然格式正确（P1_ 开头的 JWT），但在 Lever 服务端 hCaptcha 验证中被拒绝。**

#### 根因分析
Lever 使用 hCaptcha **enterprise/enclave 模式**，这不是标准 hCaptcha widget 流程。2Captcha 可能无法正确生成为 enclave 模式签名的 token，导致服务端验证失败（即使 token 格式正确）。

#### 代码更新
- `_solve_hcaptcha()` 改用 `form.submit()` 原生方式（比按钮点击更可靠）
- 2Captcha 失败时清晰提示错误原因
- 建议切换到 CapSolver 等有 hCaptcha enterprise 支持的替代服务
- 保留手动验证作为 fallback
